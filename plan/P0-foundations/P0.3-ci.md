# P0.3 Continuous integration

**Depends on:** P0.2 · **Next:** P0.4

## Why
Every change is checked automatically, so mistakes are caught before they reach a stick.

## Context
- **GitHub Actions**, using the reusable workflows in `contest-keeper/.github` (context.md §11b).
  Copy `templates/rust/ci.yml`, `rustfmt.toml`, `deny.toml` and the release-please files from
  `contest-keeper/.github/templates/` when the repository gets its first `Cargo.toml`, and add
  `cargo` to its `dependabot.yml`. The PR-title check and the `main` ruleset are already in place.
- Builds needed: Windows (admin tools, GNU toolchain) and Linux (agent via `cargo zigbuild`, API).
- Tests that need the 30 GB image or QEMU do **not** run in CI; they run locally (A.8).
  CI uses the tiny generated image from A.3.5.

## Small steps
- [x] **P0.3.1** Decide the CI platform – GitHub Actions.
- [ ] **P0.3.2** Pipeline "check": `cargo fmt --check`, `cargo clippy -- -D warnings` on Linux.
- [ ] **P0.3.3** Pipeline "test": `cargo test --workspace` on Windows and Linux.
- [ ] **P0.3.4** Pipeline "build": agent (static musl via Zig) and admin CLI (Windows) as artifacts.
- [ ] **P0.3.5** Cache the Cargo folders to keep runs fast.
- [ ] **P0.3.6** Add the CI check (`rust / check`) to the repository's `main` ruleset next to `title / pr-title`.
- [ ] **P0.3.7** Add release-please (`templates/release.yml` + config) and build the release files after it.

## Done when
A pull request shows green checks and downloadable agent + CLI builds.

## Out of scope
Releases and signing (H.8), VM tests in CI.
