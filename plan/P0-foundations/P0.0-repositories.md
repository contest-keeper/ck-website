# P0.0 Repositories

**Depends on:** nothing · **Next:** P0.1 · **Do it only when you say so** – it moves, renames and publishes things.

## Why
Contest Keeper is open source. Before new code is written, every part should live in one GitHub
organization with clear names, and big files should be out of the code folders.

## Context
- **GitHub organization:** `contest-keeper` (free on 2026-11-10; `contestkeeper` was free too).
  Only you can create it (github.com → your avatar → Settings → Organizations → New organization;
  the Free plan is enough for open source: unlimited public repositories and Actions minutes).
- **Naming rule (EASY-PLAN.md), modelled on Safe Exam Browser (`seb-*`):** one repository per
  product, `ck-<part>`: `ck-protocol`, `ck-os`, `ck-forge`, `ck-hub`, `ck-hub-setup`, `ck-extension`,
  `ck-website`, `ck-backend` (to archive), `ck-app` (future), plus `contest-keeper/.github`
  (organization front page, community files, templates). No README-only repository. Local folders use
  the same names: `D:\ck-<part>`.
- **Creating repositories:** the `gh` CLI is signed in as `robbertpopa` with the `repo` scope, so it can
  create the repositories once the organization exists (`gh repo create contest-keeper/<name> --public`).
  GitHub does not allow creating the organization itself through `gh` or the API.
- **Existing projects** (context.md §12):
  - `D:\contest-keeper` → `robbertpopa/contest-keeper`: the extension (WXT, Svelte 5, TypeScript).
    It has **uncommitted changes** – you commit or stash them first. Never touched without you.
  - `D:\contest-keeper-backend` → `robbertpopa/contest-keeper-backend`: the .NET 10 backend.
  - `D:\contest-keeper-app`: this plan, `docs/`, the prototype folder `rcpc-stick/`.
- **Transferring** a repository to an organization keeps history, issues, pull requests and stars, and
  GitHub redirects old URLs. Not carried over, or worth re-checking: Actions secrets, environments,
  deploy keys, webhooks, branch protection, GitHub Pages, and any OAuth settings that mention the old
  URLs (the backend's Google sign-in).
- Inside `D:\contest-keeper` there are things that don't belong to the extension and are **not
  git-ignored**: `rcpc-newpass.img` (30 GB, the contest image) and an empty nested Git repository
  `contest-keeper\`. (The old VirtualBox `vm\` folder and all image copies were deleted on 2026-11-10.)
- **Open source and the image:** the base image is the contest organizers' ICPC-based image with
  third-party software (e.g. JetBrains IDEs, CLion needs a license). Publish the *patch* and the tools;
  check licenses before publishing any image download.
- Shared Rust crates (`ck-protocol`, `ck-crypto`, `ck-image`) are needed by `ck-os`, `ck-forge` and
  `ck-hub`: they live in the `ck-protocol` repository, released with version tags; the others use them
  as a Git dependency pinned to a tag (later possibly crates.io).
- This Claude session works in `D:\contest-keeper-app`; renaming that folder moves the session.
