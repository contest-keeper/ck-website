# A.3 ck-image – work with image files

**Depends on:** A.1 · **Next:** A.4 · **Crate:** `crates/ck-image`

## Why
The admin tool has to put each stick's settings into the image without Linux tools, on Windows.
The EFI partition is FAT, so pure Rust can write it directly inside the image file.

## Context
- Image layout (context.md §4): GPT; EFI system partition at sector 4096, 128 MiB, FAT32 label `EFI`;
  its partition type GUID is `C12A7328-F81F-11D2-BA4B-00A0C93EC93B` (stored mixed-endian on disk).
- Settings path inside it: `ck/config.json` (+ wallpaper etc. in the same folder).
- The prototype did this in Python (extract the partition, edit with pyfatfs, write back) – it worked,
  but Rust can work **in place** on a byte range of the file (e.g. `fatfs` + `fscommon::StreamSlice`).
- Images are ~30 GB; never load one into memory. Tests use a tiny generated image (A.3.5).
- Copies must be on C: (SSD); D: is a slow HDD.

## Small steps
- [ ] **A.3.1** GPT reader: read the header (sector 1, signature "EFI PART"), the partition entries,
  return type GUID, first/last sector, name. Errors in plain words ("this file has no partition table").
- [ ] **A.3.2** Find the EFI partition and the Linux root partition.
- [ ] **A.3.3** Open the FAT EFI partition in place (a seekable "slice" of the image file).
- [ ] **A.3.4** `write_file(image, "ck/config.json", bytes)` and `read_file(...)`;
  create the folder if missing; replace existing content; flush and unmount cleanly.
- [ ] **A.3.5** Test fixture: create a small (e.g. 64 MiB) image in a temp file with a GPT and a FAT32
  "EFI" partition, generated by the test itself.
- [ ] **A.3.6** `copy_image(src, dst, progress)` with a SHA-256 of what was written; and
  `verify_image(dst, expected_hash)`.
- [ ] **A.3.7** Integration test (ignored by default, run manually): write and read settings on a copy
  of the real base image in `C:\rcpc\`.

## Done when
All fixture tests pass, and the manual test writes settings into a copy of the real image that Linux
mounts fine at boot (checked in A.8).

## Out of scope
Raw USB writing (F.1), changing the Linux partition (A.7 uses WSL debugfs).
