# D.4 Network lock

**Depends on:** D.3 · **Next:** D.5

## Why
Right now outgoing traffic is allowed (context.md §4), so a program could reach the judge without
going through Squid – and the capture would miss it. The lock makes the capture trustworthy.

## Context
- UFW cannot filter by user; **nftables** can (`meta skuid`). Rule: only the Squid user and the
  uplink's system user may open outgoing connections; everyone else may reach only `127.0.0.1:3128`
  (Squid) plus DNS and DHCP.
- The uplink reaches the API directly (not via Squid); the API host must be allowed for the uplink user only.
- Keep printing (local CUPS) and the local network (venue printers) working – check what the venue needs.
- The old `/icpc/scripts/firewall.sh` (Greek contest) stays disabled; replace UFW's role carefully.

## Small steps
- [ ] **D.4.1** nftables rule set generated by the agent from the settings (API host, platform hosts, printers).
- [ ] **D.4.2** Apply at boot before the desktop starts; fail closed if it can't be applied.
- [ ] **D.4.3** Bypass tests in the VM as `contestant`: `curl --noproxy '*' https://rcpc.kilonova.ro`,
  a Python script, a direct IP connection, DNS-over-HTTPS – all must fail; Firefox via Squid must work.
- [ ] **D.4.4** Dashboard: report the lock state in the heartbeat.

## Done when
All bypass attempts fail and normal use (judge, docs, printing) works.

## Out of scope
VPNs and USB network adapters (note as risks; covered partly by F.4's USB block).
